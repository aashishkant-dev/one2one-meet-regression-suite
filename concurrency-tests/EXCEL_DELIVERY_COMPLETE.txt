Status Column Examples:

  ✅ Pass
     Use when: "Test worked as expected"

  ❌ Fail
     Use when: "Test found a bug or unexpected behavior"

  ⏭️ Not Tested
     Use when: "Couldn't run the test"

Actual Result Examples:

  ✅ Good: "Exactly one delegate got the slot, the other got a message
           saying 'This slot is no longer available'"

  ❌ Bad: "Both delegates got confirmed to same slot. Two confirmation
         notifications sent. Double-booking bug!"

  ⏭️ Skipped: "Test setup failed - couldn't login as test account"

Comments Examples:

  ✅ "Tested 5 times, 100% consistent"
  ✅ "Response time: 245ms (good)"
  ✅ "Issue #456 - missing database lock"
  ✅ "Root cause: Concurrent write without mutex"


WHAT EACH TEST IS CHECKING:
═════════════════════════════════════════════════════════════════════════════

🧑‍💼 BOOKING RACES (TC-CC-001 to 009)
   │
   ├─ What: When two people try to book the same time slot at the
   │        exact same moment...
   │
   └─ We want: Exactly one person gets it. The other gets a friendly
              message saying the slot is taken.

   ❌ BAD: Both people think they booked it. Double-booking disaster!


👤 SESSION RACES (TC-CR-001 to 007)
   │
   ├─ What: When the same person does two opposite actions at the
   │        same time (on two different devices, for example)...
   │
   └─ We want: One action "wins", and both devices show the same result
              after refreshing.

   ❌ BAD: One device says "Accepted", other says "Rejected". Confusing!


📅 EVENT SETUP RACES (TC-CE-001 to 006)
   │
   ├─ What: When organizers edit event settings at the exact same
   │        moment...
   │
   └─ We want: Event ends up in one clean state. No data corruption.
              No duplicate events.

   ❌ BAD: Event settings confused. Meetings disappear. Data corrupted!
